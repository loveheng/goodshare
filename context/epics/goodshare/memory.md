# goodshare · Android 分享收集器 + 内嵌 MCP 服务

## 目标
- 手机使用过程中，通过系统分享菜单把「好东西」（文本 / 链接 / 图片 / 视频 / 文件）一键收集进 app
- app 内可作为 MCP 服务（Streamable HTTP）运行，供桌面 AI 客户端（Claude Desktop / ZCode 等）检索与读取收集内容
- 链路：采集（分享菜单）→ 存储（sqflite）→ 浏览检索（Flutter UI）→ MCP 对外（tools）

## 技术决策（已定）

- [2026-09-28] 第 3 档「后台常驻引擎」落地（前台服务共享 + 设备状态感知调度，用户推进）：决策——不把 `QueueConsumer` 搬到 `flutter_foreground_task` 的 task isolate。事实依据：该插件**仅支持单个前台服务**，而 `McpController.enable()` 已用它保活主 isolate（`startService` 无 callback，`eventAction: nothing`，McpServer/QueueConsumer 都在主 isolate 跑）；搬 consumer 进后台 isolate 需另开 sqflite 连接且与主 isolate 双写竞争。故取更稳路径：**复用同一前台服务保活主 isolate**，退后台时 consumer 的 3s 轮询继续消费。由此派生硬约束：`init` 收敛到 `lib/service/foreground_task_init.dart` 的 `ensureForegroundTaskInit()` 幂等统一执行（MCP/AI 各自只 `startService`），`stopService` 前必查 `mcp.running` 以免打掉 MCP 服务。调度按 V2 §3.x 落地：充电/满电/电量≥40% 且非内存压力才认领任务，否则停留 `pending`（非 failed）；`onMemoryPressure`（Flutter `didHaveMemoryPressure`）触发时暂停+回滚 pending 待续跑、不崩溃。动因：用户原规划「flutter_foreground_task 作为第 3 档（复杂离线模型推理、大批量媒体索引）的后台常驻引擎备用」。
