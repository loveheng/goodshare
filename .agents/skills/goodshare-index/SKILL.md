# goodshare 功能落点索引（规约）

> **索引数据 = `docs/project/index.md`**（数据住 docs/project/，规约住 skill——本仓既定结构原则，与 goodhub 同构）。索引机制（表格式规范、增量登记纪律）见全局 `project-index` skill，本文件不复制其正文。

## 1. 索引构成

`docs/project/index.md` 登记三块，各有专属维护协议：

| 块 | 内容 | 何时登记 / 更新 |
|---|---|---|
| **归属表** | 领域 → 覆盖功能 → 代码落点（锚点 + 展开命令）+ 文档落点 | 新领域 / 大功能落地、搬迁、改名后同轮登记 |
| **跨域隐式契约** | 机器查不出的域间联动（改动一处须同步另一处的约定） | 发现新契约同轮登记；能用测试守护的优先加护栏 |
| **业务别名映射** | 口语称呼 → 索引领域（收集器→采集域等） | 出现新的高频别称时补一行 |

## 2. 用法

1. 按归属表定位领域。
2. 以该路径为 include_pattern 限定搜索展开——展开结果只用于当前任务，禁止写回本表。
3. 定位不到时才全量 grep / find_path。

## 3. 登记纪律

- **增量登记，禁止一次性铺满**：表随实现长出来，不为「完整」预写空泛行。
- **一行一领域**：功能名可读（勿写任务号）；落点精确到文件或目录锚点（仓库相对路径，禁绝对路径）；锚点后附展开命令，展开现场 derive，不预写文件清单。
- **禁写施工过程**：日期、切片/步号、PR 交付记录、重构心路一律不进表——过程事实归 Git log 与 `context/epics/`；单格以「指针 + 一句话红线」为上限。
- **禁留路径墓碑**：路径已不存在时直接删除该指针（Git 历史可溯），不写「XX 已不存在，勿再引用」类正文。
- **禁写易腐数字**：文件数、行数、工具计数等每次提交都会漂移的数字不入表。
- **失效落点即修**：发现表中路径不存在 / 语义过期，同轮修正或删除，不留「待对账」。
- **可推导的不维护**：路径/命名现场可推导的不登记；禁止为收集目的给文件新增元数据字段、禁写类清单/文件触点清单。

## 4. 维护协议

- **新增领域/大功能加一行**，同步检查「跨域隐式契约」是否产生新联动。
- **文档落点三处同步**：新增 / 移动 / 废弃 docs/ 文档时——`docs/project/index.md`（涉及时）+ `docs/README.md` + `goodshare-docs` skill 域表（维护协议见 goodshare-docs）。
- **命令速查不进本索引**：命令与环境事实源 = `goodshare-workflow` skill。
- **索引体检（防慢性腐化）**：索引腐化是单次登记都不违规、累积后显形的过程——epic 收尾（`::done`）或重大重构后对账一次：① 落点路径存在性抽查；② 隐式契约是否已被测试护栏覆盖。发现漂移同轮修正。
