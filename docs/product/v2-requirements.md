## 1. 目的与范围

### 1.1a 收敛拍板记录（2026-10-09，用户提出、AI 对账确认）

评估结论：v2 原稿存在**战略意图（§1.3 MCP 优先）与功能设计（R1–R5）的割裂**——四处把云端全功能 Agent 体验塞进移动端 1.5B 小模型的过度设计。四项收敛：

1. **砍 R4**：编辑器回归纯文本/块编辑手感。错别字校对/文风切换交桌面或云端；Diff 高亮/CAS 还原逻辑全部不上。注：`ai_revisions` 写回快照与乐观锁是 **AI 写回可逆**（ai-writeback-revert.md，2026-10-04 已落地）的地基，非 R4 专属，保留。
2. **砍 R3**：截图价值=OCR 文本入库可搜可复制（基线已达成）。发票/名片结构化若真有需求，桌面 MCP 抓 OCR 文本用大模型清洗，端侧零投入。
3. **收窄 R1**：chatlog 输入源本就有限（§3.1 自认「来源有限」）且 OCR 碎片动辄数千字超出 4096 ctx——端侧 1.5B 理不清长聊天记录的逻辑，整理产出不可信；超长分块/Map-Reduce 基建不为此铺设（Phase 2/4 仅在向量检索需要时另行评估）。**已落码的 chatlog 分支删除**（taskParseChatlog 认领+降噪改写，约 40 行）；taskActionFor(chatlog) 回归 null（占位消化）。
4. **R5 除名**：温控方向对但「真机逐 ROM 验证」投入产出比陷阱——ROM 温控上报黑盒不值得死磕；电量门控+超时熔断+串行队列已闭环。

收敛后本期范围 = **R1(URL 摘要+打标) + R2(打码)**，两者均已落码；真机验证后本期即收官。

多源健康数据接入与 `health_record.v1` 仍推迟 V3（2026-09-27 决策），本文不再覆盖。

### 1.2 已完成基线（不在本期范围，简列备查）

以下上一版 V2 条目已落地或被后续决策覆盖，实现细节以代码与各自 SSOT 文档为准：

- **AI 接口抽象与可插拔**（原 §3.8）：`AiReconstructor` 接口 + `ReconstructorRegistry.resolve()` + `PlaceholderReconstructor` 占位回退；写路径全部收口 `ItemActionHandler` 命令化（SSOT：`../architecture/human-ai-parity.md`）。
- **设备状态感知调度**（原 §3.6 大部分）：`AiQueueService`——电量/充电门控（`canProcess`）、内存压力暂停 + processing 回滚 pending、前台服务保活、通知栏进度。
- **能力探测与门控**（原 §3.7）：OCR/转写一次性检测持久化；LLM 引擎动态探测（`isAvailable` 不持久化）+ 入队前预检；不可用回退占位、UI 明示。
- **端侧 LLM 引擎**：LiteRT-LM Kotlin 真推理（Android）/ FoundationModels 骨架（iOS），Qwen2.5-1.5B 模型下载管理，手动摘要/关键词/图片描述已可用（SSOT：`../design/on-device-llm.md`）。
- **OCR / STT**：ML Kit 中文 OCR（v1 分期调整提前）、sherpa 端侧转写 + 手动触发链路。
- **MCP `reparse_item`**（原 §6）：以 `reprocess_item` 语义落地，工具族已 16+。
- **便签编辑器非 AI 部分**（原 §5 底座）：块编辑器、块↔文本映射、行内媒体块均已落地。
- **Schema 增量登记**（原 §7 占位）：`invoice.v1` / `contact.v1` / `event.v1` 已在 `machine_json_validator` 登记必填字段。

### 1.3 范围对齐、加工主体与实施排序（2026-10-02 评估+拍板）

内容来源重心已从网页转向 **app 分享**，且**文本大头在媒体提取**：音视频转写（1h ≈ 45KB）> 图片 OCR > 网页抓取（收益下降中，维持现状不投入）> 人手写便签（最小）。OCR/转写文本已入库可搜（human_md），加工链路已全通但全手动。

**加工主体拍板（2026-10-02）**：人类端只做**当前需要**的即时操作（读、搜、单条处理、人工修订）；**繁重加工（转写/OCR/摘要/打标/结构化）交给桌面 AI 客户端经 MCP 驱动**——Human-AI 对称性（`../architecture/human-ai-parity.md`）的产品化推论：AI 是「头」，UI 是按需入口。

> 范围边界（2026-10-02 拍板）：MCP 客户端分域授权（按客户端发 token + 工具/数据/内容形态三维 scope，processed 档与 R2 打码层协同）经评估成立但**划入 V3**——V2 维持单 token + Vault 隔离的信任模型，先把 MCP 加工链路走通。SSOT：PRD §9 V3 行。

| 分享内容 | 理解层现状 | 对应需求 |
|---|---|---|
| 视频/音频（转写=文本大头） | 链路全通但 UI 手动；**MCP 无 transcribe 工具** | 配套④ + R1 |
| 图片/截图（OCR 次大头） | OCR 仅 UI 手动；**MCP 无 ocr 工具** | 配套④ + R3 |
| 聊天截图（→chatlog） | `parse_chatlog` 落占位 | R1 |
| PDF/文档 | 抽取器已建、未接队列 | 配套① |
| 公众号等真网页链接 | 离线抓取正文有效 | R1（叠加摘要） |

**配套销项**（不占 R1–R5 编号，追踪于 `context/todos.md`）：

1. **document 归一化接线**：`taskActionFor(document)` 由 null 接上队列，文件类分享自动出可读正文（content-pipeline §9 既有 Phase，接口位已存在，半天级）。
2. **预置链实施**（ui-spec §4.3/§4.4 拍板）：**随加工主体拍板降级**——人类端只保留按需轻量入口，排序殿后；预置内容仍建议含「转写并摘要」「OCR 并打标」。
3. **图文同分享文案修复**：receive_sharing_intent 只取 URI 丢文案；需 fork 插件或自写 intent 解析（原 misc 低优，随 app 分享为主升级）。
4. **MCP 媒体加工工具补齐**：新增 `transcribe_item` / `ocr_item`（动作层 `TranscribeCommand` / `OcrCommand` 已在，仅补工具定义与 CommandActor 门控核查）——最大两块文本来源当前 AI 够不着，是「MCP 优先」的前置条件。AI 编排无需新增链式基建：命令入队 + `get_item.last_task` 轮询闭环已具备（R1 可观测规则）。

**实施排序**：配套① → 配套④ → R1（LLM 通用重构器，第一消费者=媒体链：转写/OCR 产出 → 摘要+打标；R2 打码随 R1 上）→ R3 → 超长文本 Phase 2 分块 → Phase 4 向量（触发条件=媒体条目量）→ 配套③ → 配套② → R5 → R4。

## 2. 技术路线（现行口径）

**上一版「不下载、不内置任何大模型，仅调用系统级 on-device 模型」的硬约束已废止**（2026-09-28 拍板）。现行路线：

- **Android**：LiteRT-LM Kotlin 运行时 + Qwen2.5-1.5B（q8，~1.5GB）模型包，设置页按需下载；SoC 感知 NPU/GPU/CPU 降级为二阶段目标。
- **iOS**：FoundationModels framework（iOS 26+ / A17+）系统模型，零下载；不可用降级。
- 双端接口契约、模型目录、下载管理、推理桥细节以 `../design/on-device-llm.md` 为唯一事实源，本文不重复。

由此派生的口径修正（覆盖上一版对应条目）：

- 「断网验收」= **模型包在位后**断网完成全部管线（下载是一次性设置动作，不参与验收断言）。
- 「不触发任何大模型下载」验收项作废，替换为「模型未在位时全链路回退占位、不卡队列、UI 明示」。
- 系统模型碎片化风险（原 §8）随 LiteRT-LM 路线消解：Android 不再依赖 AICore/Gemini Nano。

## 3. R1 · 摄入自动双态重构管线

### 3.1 现状与缺口（已落地）

摄入链路按类型自动入队（`Repository.taskActionFor`）：url → `summarize_url`。chatlog 经 2026-10-09 收敛拍板（§1.1a）**不再入队**（`taskActionFor` 回归 null，占位消化）。

- **url**：`OcrReconstructor` 自动离线抓取网页正文写入 `human_md`（保结构 Markdown）——事实源。
- **chatlog**：~~LLM 议题整理~~已砍——1.5B 理不清长 OCR 碎片的逻辑，整理产出不可信。

### 3.2 需求（已落码，2026-10-09 收敛口径）

`LlmReconstructor` 认领 `summarize_url`：在既有「离线抓取正文」之上叠加 LLM——TL;DR 摘要（`summary_md` 并列，不改写正文）+ 2–3 自动标签（D2：直接进 tags，并集只增不删）。

- **链式触发**（D4）：抓取任务成功后自动链入摘要任务（产出特征闸：LLM 产出带 summaryMd 天然终止 + 轮内单链闸防自链死循环）；「自动摘要」开关默认开。
- **超长口径**（D3）：超 3000 字符回退占位 + note 明示，不截断照跑。
- **可观测**：产出/失败原因遵循既有 R1 规则——同一份文案进 UI 任务状态条与 MCP `last_task.note`。
- ~~`parse_chatlog` 降噪整理~~砍除（§1.1a）；taskParseChatlog 常量保留（历史任务行兼容）。

## 4. R2 · 隐私打码层（已落码）

AI 产出**必经本地规则层**（端侧，不外传），已按 D1 拍板挂**通用出口**：

- 规则：18 位身份证号（regex + GB 11643 校验位）、银行卡号（13–19 位 + Luhn 校验）→ 默认 `****` 打码（长编号边界守卫防误伤）；「身份证 / 银行卡默认打码」开关接线（默认开）。
- 作用面：`_applyAiResult` 出口处 `human_md` 与 `machine_json` 同步打码，**覆盖所有 AI 写路径含占位回退**；`raw_content` 保留明文。
- 落点：`lib/ai/privacy_mask.dart` 纯函数 + `ItemActionHandler.isMaskEnabled` 注入（UI/MCP/管线换入口也绕不过）。

## 5. R3 · ~~通用截图解析~~（砍除，2026-10-09 §1.1a）

**整条砍除，未动工零返工**。理由：截图价值 = OCR 文本入库可搜可复制（基线已达成）；端侧 1.5B 零样本领域分类 + 严格 Schema 结构化的字段填充率与格式遵从度不可信，验证器/容错/降级投入为极低频场景建重基建。发票/名片结构化属**重活**——归桌面 AI 客户端经 MCP 抓 OCR 文本批处理（§1.3 加工主体拍板的直接推论）。`invoice.v1`/`contact.v1`/`event.v1` validator 登记保留（Schema 定义零成本，供桌面端/未来复用）。

## 6. R4 · ~~便签编辑器 AI 增强~~（砍除，2026-10-09 §1.1a）

**整条砍除，未动工零返工**。理由：① 1.5B q8 的中文校对必然海量误报/漏报，高亮打断记录心流；文风切换产出不可信、用户不敢采纳；② 为低频伪需求铺 Diff 高亮 + 版本快照还原 + CAS 冲突仲裁，是给本地单人文档做协同级工程——过度工程。编辑器回归纯文本/块编辑手感；校对/改写需求交桌面或云端。注：`ai_revisions` 写回快照与乐观锁是 **AI 写回可逆**（ai-writeback-revert.md）的地基，非 R4 专属，保留。

## 7. R5 · ~~温控节流~~（除名，2026-10-09 §1.1a）

**从需求表除名**。防过热已由既有三件套 100% 覆盖：电量门控（`canProcess`）+ 单任务超时熔断（60s~600s 分档强杀）+ 队列严格单线程串行。「真机逐 ROM 验证 ThermalStatus 上报」是 ROM 黑盒里的精力陷阱，不做。

## 8. MCP 与 Schema 增量（收敛后）

- **MCP 零新增工具**：模型升级后的重放由既有 `reprocess_item` 承担；所有产出经 `get_item` 可读、失败经 `last_task.note` 可观测（Human-AI 对称性既有规则）。
- **重活归 MCP**（收敛拍板的正向落点）：截图结构化、长文校对/改写等端侧砍除的能力，桌面 AI 客户端经既有工具族（`get_item` 取 OCR/正文 → 云端大模型加工 → `add_item`/`update_item` 回写）即可完成，app 零新增。
- **Schema**：`invoice.v1` / `contact.v1` / `event.v1` validator 登记保留（零成本，供桌面端复用）；`machine_json` 取值本期无扩展，**无需新建表**。

## 10. 验收标准（收敛版）

- [ ] 模型包在位 + 断网：分享一条 URL → 抓取正文后自动产出 TL;DR 摘要（`summary_md`，正文不改写）+ 2–3 标签，`is_processed=1`。
- [ ] 「自动摘要」开关关闭：URL 仅抓正文，不链摘要任务。
- [ ] 超长正文（>3000 字符）：回退占位 + note 明示「内容超长」，不产出失真摘要。
- [ ] 模型未下载/引擎不可用：回退占位（原样 human_md），队列不卡、note 明示原因。
- [ ] 身份证/银行卡号出现在 AI 产出中 → `human_md`/`machine_json` 默认打码（含占位回退路径），`raw_content` 不动；设置开关关闭后不打码。
- [ ] chatlog 条目摄入：不再自动入队 LLM 整理（占位消化），OCR 文本照常入库可搜可复制。
- [ ] 全流程端侧完成，无任何云端推理请求。
