# 内容管线设计：富文本归一化 + 文件引用策略

> 两件事本是一体：**内容怎么呈现**（富文本归一化 + 自建渲染）与**文件怎么持有**（引用原件，app 不占用户存储）。
> 起因：UI 进入「页面排布与展示形式」阶段，参考 mymind 的**文档形态**（详情页是文章，不是仪表盘；弃用小红书式低密度大卡片）；顺带暴露出两处根因——① 上游把富文本降级成了纯文本，② 附件复制一份导致视频存储翻倍。
> 决策拍板于 2026-09-29（多轮 @confirm 收敛）。

## 1. 关键决策

| 决策点 | 结论 | 依据 |
|---|---|---|
| 呈现基调 | **文档形态**（mymind 详情页范式），弃低密度大卡片 | 内容是「存下来再读」，不是「逛」；密度高 = 不浪费像素在非内容上 |
| 渲染方式 | **自建轻量富文本渲染器**，弃 `flutter_markdown_plus` | §5 四条理由；该包是原包停更后的社区分叉 |
| 富文本载体 | **Markdown 子集**（存储格式不变） | `human_md` 本就是 Markdown，MCP 输出契约零改动；明确不引 HTML 渲染包 |
| 存储与呈现 | **存储分层（raw → 富文本 → 机器态 三层照旧），呈现归一（只渲染富文本）** | `raw_content` 常是唯一副本（便签/链接），不可抛；呈现层暴露原始层正是当前 UI 缺陷根源 |
| 文件持有 | **引用原件，app 不复制**（不给用户存储添麻烦） | 用户拍板；导入 = 1 份，复制 = 2 份 |
| 文本类留存 | 归一化富文本入库即**内容本体**，副本可释放 | 文档类「转换后释放副本」= 零占用且内容自持 |
| 媒体类留存 | 引用整片 + 缩略图/关键片段自持 | 富文本替代不了媒体本体；视频文本化成本高（§7） |
| 提醒 | 分享摄入后**弹提醒 + 快捷导入** | 分享 URI 生命周期短，事后补位来不及 |

## 2. 呈现形态：文章，不是仪表盘

详情页从「分区卡片堆叠」改为「文档流」。mymind 范式的四条语法：

- **标题置顶**（`headlineSmall` w600），导语在其下
- **正文全宽排版**，空间全给内容
- **chrome 极低**：操作收进 AppBar `⋯` 菜单
- **主操作唯一**：底部一个浮动按钮，不是一排 `OutlinedButton`

现有详情页改造对照（详见 `ui-spec.md` §4.3）：

| 现在 | 改成 |
|---|---|
| TL;DR 用 primary 色文本置顶 | 正文前**导语块**（次级色 + 左侧细线） |
| 标题在 TL;DR 之下 | **标题置顶** |
| 机器态 Switch 常驻 | 收进 `⋯` 菜单（双态是架构灵魂，入口保留但降权） |
| 图片/播放器在正文之上 | 内联进内容流 |
| 摘要/译文/关键区间 各自 Card 堆叠 | 正文末尾**附录章节**（小标题 + 内容），不叠卡片边框 |
| 转写/提取音轨/切片 等按钮矩阵 | 收进 `⋯` 菜单；底部浮动按钮只留主操作 |
| 无 | 正文末尾小字「来自 XXX · 2026-09-29」 |

## 3. 富文本载体：Markdown 子集

**块级**：`#`~`###` 标题 / 段落 / `>` 引用 / `-`、`1.` 列表 / ``` 代码块 / `---` 分隔 / `- [ ]` 待办（可勾选行）。

**行内**（`TextSpan`）：`**粗体**` / `*斜体*` / `` `行内码` `` / `[文字](链接)`（不可点，不引 `url_launcher`）。

**不做**：表格、脚注、HTML 混排、嵌套引用 —— 一律降级为纯文本段落。
**铁律：宁可样式平，不可吞内容。**

## 4. 归一化层（`lib/doc/`）

与 `AiReconstructor` Registry / `ItemViewRegistry` 同构——新增格式 = 实现 + 注册，框架零改动。

```text
lib/doc/
├─ normalizer.dart      DocumentNormalizer 接口 + Registry（按扩展名/MIME 分发）
├─ html_to_md.dart      网页抓取 → 富文本
├─ pdf_to_md.dart       pdfx 提取 → 富文本（启发式结构）
├─ plain_to_md.dart     txt / OCR / 转写 → 段落块
└─ (docx 留插槽：接口已备，实现不做)
```

| 输入 | 转换器 | 保真度 | 备注 |
|---|---|---|---|
| `md` | 直通 | 高 | — |
| `txt` | 空行分段 → 段落块 | 中 | 无层级 |
| `html` | h/ul/ol/blockquote/pre → Markdown | 高 | **现 `url_extract.dart` 丢全部结构，须补** |
| `pdf` | pdfx 提取 + 字号/位置启发式判标题 | 中低 | **DEGRADE**：启发式，命中即标题，否则段落 |
| OCR / 转写 | 纯文本 → 段落块 | 低 | 源本身无结构 |
| `docx` | **不做** | — | OOXML 解析代价与收益不成比例；退化为文件卡 + 系统打开 |

产物落点：**写 `human_md`**（不新增列）。语义即「人类可读正文」，AI 重构时自然升级覆盖；需重转走既有 `reprocess` 通道。

## 5. 自建渲染器（弃 `flutter_markdown_plus`）

四条理由，按硬度排：

1. **待办勾选在渲染器架构下永远做不了**——Markdown 渲染器输出不可交互文本流，而 `ui-spec` §7 要求 `human_md` 中 `[ ]` 可勾选、状态写 `todo_state_json`
2. 该包是原包停更后的社区分叉，长期维护不确定
3. 文档感全靠排版参数，受限于渲染器内部结构
4. 全仓仅 2 处引用，替换成本极低

排版令牌（文档感来源）：正文 15.5-16px / 行高 1.65 / 段间距 14；h1 22 w600、h2 18 w600、h3 16 w600；引用左侧 3px 竖线 + 次级色；代码块 `surfaceContainerHighest` + 等宽。

**长文门控（硬约束）**：`url_extract` 抓取上限 20000 字，一次性构建全部 widget 必掉帧 → 超阈值截断 +「展开全文」。

## 6. 文件持有策略矩阵

| 来源 \ 类型 | 文档类（pdf/txt/md） | 媒体类（image/video/audio） |
|---|---|---|
| **导入**（app 内选） | 引用 → 转换 → **释放副本**（零占用） | 引用，**1 份** |
| **分享**（外部 app） | 引用 → 立即转换 → 释放副本 | 引用 + **弹提醒 + 快捷导入** |

硬约束：

- 分享进来的是 `content://` URI（非文件路径），只有读权限，**无删除通道**（FileProvider 未实现 `delete`）——「导入即删原件」在技术上不可行，且破坏性动作不采纳。
- 引用必须走 **SAF + `takePersistableUriPermission`** 存 URI，**不能存裸路径**（分区存储下会失效）。⚠️ 现 `file_picker`/`image_picker` 能否拿到可持久化 URI **待实测**；且需确认选择器自身缓存副本是否长期残留。
- **视频文本化不可行作为常规流程**：转写需提音轨 + 跑模型，且转写文本 ≠ 视频内容（画面全丢）。现状已是手动触发（`taskActionFor(video)` → null），不动。

## 7. 引用状态机 + 提醒与快捷导入

```
ref（引用中，未复制） ──用户点导入──▶ owned（已持有副本）
        │
        └──原件失效──▶ lost（不可访问）
```

新增列 `attach_state`（schema v12）：`ref` / `owned` / `lost`。

三处 UI：

1. **分享摄入后立即弹提醒**（用户拍板）：「这是临时引用，原件删除或授权失效后将无法打开 · [导入到拾贝]」
2. 条目标记：引用中的条目带小标识，区别于已保存
3. 失效态 `lost`：明确说「原件已不可访问（可能已删除或授权过期）」——**不是 `broken_image` 图标了事**（R1：错误要被感知）

导入动作：复用 `copyToAppDir` → 更新 `rawFilePath` → 状态转 `owned`；大文件走前台服务 + 进度。

**分级提醒**：转换质量高（txt/md/结构完整网页）静默完成；有损（PDF 启发式、表格降级、超长截断、原件不可达）才提示。确认页须暴露覆盖率（页数/字数/降级块数），否则是假确认。

## 8. 对既有机制的影响

| 机制 | 影响 |
|---|---|
| **S3 备份** | 引用的原件**不进备份**（备份时可能已不可读，换机后路径无效）；备份内容 = 富文本 + 小衍生物（缩略图/字幕/译文/切片片段）。须改 `s3-backup.md` 附件白名单 |
| **视频切片** | 引用整片 + 自持关键片段，与已落地的 `clips_json`/`clip_segments/` 天然衔接，不新增转写负担 |
| **队列** | 文档归一化：小文件同步，大文件/PDF 走 `ai_task_queue`（新增 `normalize_doc` 动作），复用超时/降级/`last_note` |
| **列表呈现** | 密度提升：标题 1-2 行 w500 + 正文摘要 + 元信息行；缩略图 56-64px；去 `Divider` |
| **存量数据** | 已复制的保持不动（新旧混合，UI 区分「已保存 / 引用中」）；**不自动清理**（等于 app 主动销毁用户数据） |

## 9. 实施顺序

顺序不可颠倒——**先转换，再切引用**。反了会导致内容没留住却已无副本。

1. `lib/doc/` 归一化层（纯 Dart + 单测，不碰 UI）
2. 富文本渲染器（块级 + 行内，纯函数先行）
3. 文档类「转换 + 确认」闭环（`doc_meta_json`）
4. 小衍生物自持（缩略图等）
5. 可达性检测 + 三级提醒 + 快捷导入
6. **切引用模式**（`attach_state`）
7. 备份策略改造、存储占用展示、详情外壳文档化
