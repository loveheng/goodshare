# 便签内嵌视频（附件态）设计

> 便签（速记）页面支持内嵌视频，视频定位为**附件/佐证**而非内容主体。本文档覆盖双来源路径、附件态门槛、交互反馈与内存纪律。视频升格为主体的场景见 [video-subject.md](video-subject.md)，选区间交互见 [video-trim.md](video-trim.md)。

## 1. 定位与路径优先级

便签心智是「随手收集一条内容」，视频在其中是附件。两条来源路径**优先级不对等**：

| 维度 | 相册选择（主路径） | 相机直拍（次路径） |
|---|---|---|
| 用户意图 | 「我看到/拍到过一段内容，想归档」——收集心智 | 「我现在录一段」——创作心智，链路长 |
| 内容可控性 | 视频已存在，时长/大小可**先验** | 拍摄中用户无感，只能后验 |
| 交互成本 | 一次系统选择器 | 切相机 UI → 录 → 停 → 确认 |

入口收敛到附件面板「拍摄 / 从相册选择」二选一，**相册选择放首位**。直拍首版直接用系统 `image_picker`（自带 `maxDuration` 参数），不自建相机 UI。

## 2. 附件态门槛（三条约束，用户只感知时长）

核心手法：**同一条规则在两条路径以不同时机施加**——拍摄时前置限制，选择时后置校验。用户永远只感知时长，不感知字节数。

| 约束 | 相册选择（后置校验） | 相机直拍（前置限制） |
|---|---|---|
| 时长 | ≤ 5min，超限**非阻断提示**（「视频较长，嵌入可能加载慢，仍要添加？」）——长视频归档是合法诉求 | `image_picker maxDuration` ≤ 60s，到时**自动停止**（无感中断，不报错） |
| 格式 | 用户零感知；**白名单 MP4/MOV 直接入库不转码**（2026-10-01 拍板：扩大原生白名单，播放器原生可播；.webm/.avi/.mkv 等边缘格式硬拦截提示「暂不支持该格式，建议使用 MP4 或 MOV」，**不引入 FFmpeg 软编软解**——将来压缩走系统硬件编码器另期） | 相机参数直接约束，天然合规 |
| 大小 | ≤ 50-100MB，超限提示「视频过大」建议剪短（拦截引导见 [video-trim.md](video-trim.md)） | 由「时长 60s + 分辨率 720p」间接控在阈值内 |

门槛常量集中定义（媒体策略常量文件），不散在 UI 判断里——阈值几乎必然随真机数据调整。

不做精确到秒的裁剪编辑器（那是 [video-trim.md](video-trim.md) 的事），附件态不做格式概念暴露。

## 3. 交互反馈（Local-first 三件套）

- 选完/拍完立即出**封面缩略图**占位——视频必须有可辨认的首帧封面卡，不能是裸文件名；封面提取走 Job 化（重开销路径约束，见 [video-clips.md](video-clips.md)）。
- 转码/压缩期间给进度或转圈态；失败给「添加失败，点击重试」降级，不红屏（异步三态硬规则）。
- 即时关闭输入 sheet + 一次性成功 SnackBar + 靠订阅自动刷新。

## 4. 呈现与内存纪律

- 列表/详情里视频以「封面卡 + 播放按钮」呈现，**点开才加载播放器**——长列表绝不能实例化多个播放器。
- 行内视频块形态沿用 [rich-text-media.md](rich-text-media.md) §3 的 VideoBlock（占位卡 + 点按进全屏浮层，行内不常驻播放器）。
- **作曲器（草稿态）视频卡点按可预览**（2026-10-01 真机反馈用户提议）：复用详情同一全屏播放器、同一 `local://` 链路，草稿态即给用户「添加了什么、能不能播」的确认机会；保存前后同源无分叉。
- 播放器配对 `dispose()`；缩略图显式 `cacheWidth`；大视频不进 imageCache（富媒体内存水位纪律，见 `goodshare-mobile` skill）。
- 播放失败文案**带真实原因**（如硬解不支持的编码格式），不吞成统一「加载失败」（R1 口径；实测 yuv444p 编码视频 Android 硬解不可播）。

## 5. 存储与备份

- **拍摄路径 = App 内自建拍摄页**（2026-10-01 用户拍板「自建拍摄页＋进度环」，推翻原系统相机路径）：系统相机录制界面是相机 Activity，App 无法在其上叠进度 UI，60s 自动停不可感知。自建页（`note_video_capture_page.dart`，`camera` 官方插件）= 取景器 + 快门（未录=圆键启动 / 录制中=外圈 60s 进度环 + 红色停止方块）+ 倒计时文案 + 到点自动停 + 取消丢弃临时文件。页面只产 ≤60s mp4 路径 pop 回作曲器，门槛校验照走统一链（本页零写库）。
- 门槛内收进来的视频（直拍 60s、相册选的 ≤500MB 内、轻剪辑切出的副本）**进备份**——「收进来 = 系统认可 = 进备份」单一明面规则，见 [video-subject.md](video-subject.md) §4。
- 落盘走 `local://` 既有媒体链路（与 `note_composer` 拍照/录音同构）。

## 6. 前置依赖（已知坑，留待实测）

> ✅ **已解决（2026-10-01 落地时确认）**：`image_picker` 选取/拍摄后本就把文件复制进 app cache，链路默认即「复制进沙箱」= 原降级预案，可持久化 URI 不再是前置实测项。
