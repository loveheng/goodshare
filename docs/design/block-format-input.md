# 编辑态格式输入（先选后打，方案蓝本）

> [!NOTE] 状态：**active**——代码全部落地（406 测试绿）；§4.2 风险项仅剩真机验收。渲染层已由「叠层 Stack」改版为「原生 buildTextSpan 单控件」（§4.1，2026-10-03）。

## 1. 背景与目标

详情页编辑态当前为逐块 `TextField` 纯文本输入（`_EditBody` + `EditSession`，见 `detail-two-zone.md`），阅读态为自研 Markdown 子集渲染（`RichTextView` + `MarkdownSubsetParser`）。用户在编辑态没有任何格式手段，只能手打 md 符号。本方案给编辑态补一套**格式输入**能力：先选格式、后打字，打出的内容直接呈现所选样式。核心拍板：**编辑区内严禁出现 md 语法标记**（`**` 空壳类标记对用户造成困惑，用户明确否决「md 标记直出」方案）。

## 2. 决策台账（2026-10-02 逐条拍板）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 格式按钮常驻位置 | **键盘上方工具条**：文本块聚焦时出现、失焦消失，只放一个「格式」按钮（预留扩展位） |
| 2 | 子选项交互 | 点击「格式」→ 按钮上方浮出一排预设格式按钮（一级标题/二级标题/正文/加粗/斜体/下划线）；**选择后立即收起**，未选超时自动收起（时长实现期定，建议 ~4s） |
| 3 | 格式模型 | **先选后打**（输入态）：格式作用于之后输入的文字，**不做**给已有文字套格式（无选区交互） |
| 4 | 块级格式（标题/正文） | 当前块立即变类型并换 TextField 样式（真所见即所得，块级无标记问题）；**回车后新块自动回正文**（非持续态，防整篇误成标题） |
| 5 | 行内格式（加粗/斜体/下划线） | **不换编辑器**，自研 md 解析样式化编辑层实现无标记所见即所得（用户拍板，接受实现风险，见 §4） |
| 6 | 下划线语法 | **`<u>` 标签**（md 生态事实标准，桌面端多数渲染器兼容）；`MarkdownSubsetParser` 与阅读态渲染器同步扩展 |
| 7 | 行内闭合 | 再点一次同格式按钮关闭；切换其他格式/失焦/回车时**自动收口**（杜绝未闭合标记落库） |
| 8 | 格式态指示 | 「格式」按钮**显示激活态**（高亮/文案随当前格式变化），用户始终知道自己在什么格式下打字 |

决策演进备注：行内格式最初选「md 标记直出」（编辑时可见 `**`），随后用户修正为「不要出现 md 语法」→ 最终落「自研样式化编辑层」。本文以最终口径为准。

## 3. 交互规格汇总

### 3.1 格式输入全流程

```mermaid
flowchart LR
    A[文本块聚焦] --> B[键盘上方工具条出现]
    B --> C[点「格式」按钮]
    C --> D[上方浮出一排预设格式按钮]
    D -->|选中某格式| E[格式态激活 按钮显示激活态 排按钮收起]
    D -->|超时未选| B
    E --> F[用户打字 所见即所选格式]
    F -->|回车| G[新块回正文 块级格式态复位]
    F -->|再点同格式/切换/失焦| H[行内 span 自动收口]
    H --> F
```

### 3.2 各格式行为细则

| 格式 | 激活后效果 | 结束条件 |
|---|---|---|
| 一级标题 | 当前块变 H1（md 存 `# `），TextField 呈现标题样式 | 回车 → 新块回正文；选「正文」切回 |
| 二级标题 | 当前块变 H2（`## `），同上 | 同上 |
| 正文 | 当前块回正文样式 | —（本身就是复位项） |
| 加粗 | 光标处开启粗体 span，新打字符呈粗体 | 再点一次/切格式/失焦/回车自动收口 |
| 斜体 | 同上，斜体 span（`*`） | 同上 |
| 下划线 | 同上，`<u>` span | 同上 |

- 行内 span 落库即标准 md（`**粗**` / `*斜*` / `<u>下</u>`），存储层与 MCP 无感知，**不需要**动 schema/动作层。
- 阅读态渲染：加粗/斜体为 `MarkdownSubsetParser` 既有能力；`<u>` 为新增解析分支（编辑态与阅读态同源，防两套口径漂移）。

## 4. 技术方案（自研样式化编辑层）

约束前提（用户拍板）：不引入富文本编辑组件（super_editor/quill 类），不重构 `EditSession` 逐块体系，用自建解析能力实现所见即所得。

### 4.0 选型记录：为什么不换编辑器（2026-10-02 拍板）

「换富文本编辑器是否改动更小」曾作为疑问提出，评估结论是**否**——换编辑器是更大的改动，只是换了一种「大」法：

- **换编辑器要动的**：①`EditSession` 整个事务体系（CommitTextOp/SplitOp/ReplaceMediaOp、取消回滚、块 id/ValueKey）重映射到三方文档模型；②编辑态文本块与媒体块混排 UI 在三方编辑器节点体系里重新宿主（最易被低估的工作量）；③新增 md ↔ 编辑器模型双向转换层（有损风险，现体系 md 即存储原貌无转换层）；④三方包自身风险（中文 IME 组合输入、M3 接入、维护活跃度）；⑤焦点回收/标题就地编辑/TL;DR/标签/灵感区衔接全部重验。多页面代码跟着动。
- **自研叠层要动的**：新增样式化渲染层（复用 `MarkdownSubsetParser`）+ FormatState 状态机 + `<u>` 语法分支；EditSession、媒体混排、焦点体系、md 存储全不动。代价是光标/选区对位的永久脆弱层 + 后续每种新格式都要手搓。
- **裁决依据**（用户原话口径）：现需求只是便签的所见即所得，「不能为所见即所得做拆房子的事」。改动面小的路线胜出。**翻案条件**：若产品路线确定编辑器要持续长能力（列表/代码块/高亮等成体系引入），届时重新评估换正道编辑器的总成本，本节随之废弃重写。

### 4.1 分层

1. **输入层**：保留逐块 `TextField` 承接键盘输入与光标/选区管理（EditSession/CommitTextOp 事务体系不动）。
2. **渲染层（2026-10-03 改版：原生 buildTextSpan 单控件，叠层 Stack 退役）**：span 块的 `TextField` 挂 `_SpanEditingController`（重写 `buildTextSpan`，runs → 样式 TextSpan 树）——文字、光标、选择柄、换行**同一次排版**，结构性消灭叠层位移（英文粗体字宽差累积偏移从根上不存在）。逐字符标记集合合成 + 相邻同集合段合并；IME composing 区间作为独立维度并入集合（组合期下划线不丢）；`strutStyle: StrutStyle.fromTextStyle(base, forceStrutHeight)` 抹平行内码 monospace 混排的基线差；controller 内禁正则/解析（runs 增量随动全在 `EditSession.applySpanInput`，纯内存映射红线）。原「下层 Text.rich + 上层透明文字」双层叠层及其对位前提（同 base/isCollapsed 同原点）整体删除。改版动因：叠层的「同 base 样式」零位移前提被行内样式本身（粗体/斜体字宽差）打破，属物理不可解；buildTextSpan 是 Flutter 官方公开 API（TextEditingController 虚方法），代码编辑器做语法高亮的标准路数。
3. **状态层**：`FormatState`（当前块级类型 + 激活的行内 span 栈），随格式选择/回车/失焦流转；落库时由状态层把 span 序列化回 md 标记，**序列化与解析同源**（同一份语法表）。

### 4.2 已知风险（2026-10-03 随渲染层改版收缩）

- ~~光标/选区/滚动与上层样式绘制的对位~~——**已随叠层退役结构性消除**（文字与光标同一 TextPainter 一次排版，无第二布局可错位）；
- 行内 span 中途插入文字（光标点进已有粗体文本中间继续打）的 span 归属判定——数据层 `adjustRuns` 已实现，真机验证手感；
- 复制粘贴进样式化区域的内容归一化——`_SpanPasteNormalizeFormatter` 已实现，真机验证；
- 单块超长文本（数千字）逐键 `buildTextSpan` O(n) 重建——有记忆化防线待加（text+runs 版本号缓存），当前量级（便签段落）无感，真机长块滚动一并观察。

## 7. 回车拆块与性能防线（2026-10-04，输入阻碍审计 P2 收口）

统一作曲编辑器（速记+详情编辑同源）2026-10-04 落地「回车拆块」交互语义与三项性能防线，本节为 SSOT：

### 7.1 交互语义（用户拍板：Enter=新块）

- **Enter = 拆块**（新 ParagraphBlock，md 段间 `\n\n`）：软键盘与物理键盘同路（物理回车经 IME 落为文本变更，与软键盘同判据——变更插入文本含 `\n` 即物化为段边界，`\n` 本体不进任何段）；
- **Shift+Enter = 块内软换行**（md 段内 `\n`，阅读态渲染为直接换行）：物理键盘在段级按键门拦截手动插入；软键盘无 shift 语义不可用（业界同局限）；
- **多行粘贴 = 逐行拆段**：粘贴归一（空行折叠为单换行）后按行物化为独立段——剪贴板段落结构保全（取代旧「粘贴空行折叠塞进同段」）；
- **空块保存折叠**：`serializeNoteMd` 既有口径（空文本段不落 md），会话内可敲出空行、保存后收敛；
- **undo 连击**：连打带敲回车合并为一步撤销（`_beginStructuralStep(asTextEdit)` 与文字连击同窗）。

### 7.2 性能防线（击键路径 O(n)→O(k)，k=所在段长度）

| 防线 | 落点 | 实测（10k 字符段隔离基线） |
|---|---|---|
| 段级 memo 序列化 | `NoteComposerEditor._draftRows`：onDirty 只重序列化变更段，行编码形状仍走 `noteSegsToDraftRows` 单段调用（SSOT 不复制） | 序列化 1119us→O(变更段) |
| 渲染区间扫描线归并 | `buildSpanTextSpan`：逐字符 Set 数组退役，runs/levelRuns/composing 端点事件单趟扫描产 O(r) 个样式段 | **4591→70us/击键（66×）** |
| 宿主解耦 | 详情页摘除每击键整页 setState（底栏只依赖 `_editing`）；速记 CTA 改 `ValueNotifier` + `ValueListenableBuilder` 局部刷新 | 整页 diff 归零 |

基准锚点：`test/editor_perf_bench_test.dart`（10k 字符段 × 50 击键，三段分测，上限断言从宽、数字供前后对比）。回车拆段落地后段落天然千字级，`adjustQuickNoteLevelRuns` 全行重扫暂留（若未来再出现超长单段再做窗口局部化）。
