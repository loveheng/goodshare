# 视频主体条目（宽门槛准入）设计

> 视频升格为**内容主体**的场景：用户从系统文件/相册选一个视频，这条目语义是「为这个视频做说明/配图/注解」（视频为纲，文字图片为目）。主体态设**宽而非零**的门槛——目的是挡住「把手机当存储桶」的滥用（监控录像、整场会议、电影），不是限制正常收集。附件态见 [note-video.md](note-video.md)，选区间交互见 [video-trim.md](video-trim.md)。

## 1. 核心原则：限制策略跟着场景心智走

| | 视频为附件 | 视频为主体 |
|---|---|---|
| 用户意图 | 「顺手收一段」 | 「我要为这个视频写点什么」 |
| 投入意愿 | 低，秒级决策 | 高，已接受「这条记录比较重」 |
| 门槛正当性 | 有（保护列表性能与存储） | 有但宽（划产品边界，非限制正常使用） |

用户显式选择（完整的选择动作）**压倒**系统启发式——门槛内的视频不提示、不劝退、不确认；门槛的存在意义是**定义产品边界**（拾贝不做视频托管平台），超门槛意味着文件越过了产品边界，故**拦截式拒收**而非劝退式。

## 2. 两级门槛矩阵

门槛与附件态**差一个数量级**（否则两入口失去语义区分）。超限拦截直接拒收，带明确原因 + 建议语「建议先剪辑后添加」+ 一键进入轻剪辑（[video-trim.md](video-trim.md)），不提供「仍要添加？」。

| | 附件视频 | 主体视频 |
|---|---|---|
| 时长 | 直拍 ≤60s / 选择 ≤5min（超限非阻断提示） | ≤ 10-15min（拟 10min，超限拦截拒收） |
| 大小 | ≤ 50-100MB | ≤ 500MB-1GB（拟 500MB，超限拦截拒收） |
| 门槛内 | 收，无提示 | 收，无提示 |
| 超门槛 | 提示，可坚持（劝退式） | **拒收 + 原因 + 引导轻剪辑**（拦截式） |

数字依据：监控/会议/电影几乎全部 >1GB 或 >1h，500MB/10min 拦掉 99% 滥用；课程片段、vlog、产品演示几乎全部低于此。用户无需感知确切数字——门槛只在超限时现身。

**旧规则废除（限视频）**：`content-pipeline.md` 原拍板的「大文件阈值 100MB 以上额外确认」**对视频作废**，按场景门槛取代（主体态门槛内即系统认可，无需二次确认）。未来新增大文件类型（长录音、压缩包等）按场景各定门槛，**不得回退到通用 100MB 确认**。门槛常量集中定义（与 [note-video.md](note-video.md) §2 同一常量文件）。

## 3. 入口分叉（语义由入口表达）

**不靠系统猜「视频是不是主体」，靠入口表达**：

- 附件添加面板：「添加视频（附件）」——走 [note-video.md](note-video.md) 窄门槛；
- 顶部 `＋` 菜单（导入类入口）：「视频条目（为主体）」——走本文档宽门槛，产生新 `item_type`。

用户选入口即选语义，零判定成本。**严禁隐式推断**（按「有无配文/配图」反推是否主体）——推断有歧义且导致同类视频呈现不一致。新 item_type 走 `ItemViewRegistry` 注册实现模板（框架零改动）。

## 4. 门槛 = 备份准入线（明面规则）

> **收进来 = 系统认可 = 进备份**。三道门（门槛准入 → 落库 → 备份）用同一把钥匙。

`s3-backup.md` 原 D3 拍板「视频源文件不进备份」的本意是防超门槛整片拖垮备份——超门槛视频现在根本收不进来，故 D3 **收窄为精确化而非推翻**：「不进备份」对象收窄为**引用型/未收进场景**（SAF 引用、切片原片仍在外的整片本体）；**门槛内收进来的视频（附件短视频、主体视频、轻剪辑切出的副本）进备份**。

判断条件只有一个：**过了门槛收进来的就在备份里**。不按来源区分、无特例表——用户和开发不留隐形逻辑坑，一切在明面。工程侧现成：s3-backup 已有 >100MB 自动 Multipart Upload（16MB/片），500MB 视频备份链路无需新工程。

## 5. 门槛内的工程防线（后台调度，用户无感）

不干预大小 ≠ 不设防线——防线从「用户面前拦截」后移到「用户背后调度」：

- **封面/缩略图**：提取走 Job 化（重开销路径约束），列表只渲染封面卡，永不加载视频本体；
- **转写/解析**：大视频 AI 处理排队后台跑，不阻塞交互；长视频转写的临时文件与超时风险见既有 `(风险)` 条目（16k WAV ~115MB/小时、10 分钟超时未覆盖视频）；
- **播放**：详情页 video 条目保持「常驻播放器（单实例、离页即释放）」形态（OCR 转录稿跳转依赖，见 rich-text-media §6）；
- **大文件播放首帧等待**：给骨架/占位（异步三态），不让用户以为坏了——「不干预」原则下唯一要兜的体验底。
