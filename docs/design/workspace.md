# 工作区管理闭环：删除守门与清空链路（交互设计稿）

> [!NOTE] 状态：**active**——2026-10-05 三项拍板（§5）已落码：守门下沉动作层 + UI 长按弹层（重命名/删除）+ B 快捷删；真机复验待装机。设计共识即写即落。

## 1. 背景与现状

工作区功能已上线两层形态（ui-spec §4.11，2026-09-30 D2 拍板卡片化）：列表层 2 列卡片网格（封面拼贴+条目数）、条目层瀑布流双列；条目层批量选择已接 `SelectionController`/`SelectionActionBar`（card-batch-selection 配置）；**「移出本工作区」已于 2026-10-05 转正落地**（批处理条第五动作，§3.3）。

缺口：UI 层没有任何删除/重命名工作区入口（用户视角「工作区不能删除」）；命令层 `DeleteWorkspaceCommand`（op=delete_workspace）与 MCP `delete_workspace`（第 8 工具）已存在——`_deleteWorkspace` 级联清理 workspaces/workspace_items 关系行，**条目本身不受影响**。

关键语义（一切交互的前提）：**删工作区 ≠ 删内容**。删除只解除归属，条目全部保留在「全部」；条目软删另有 30 天回收站（delete_item 链路）。

## 2. 语义红线与口径

1. **计数口径与列表同源**：守门条数必须走 `listWorkspaceItems` 同口径（排除 Vault 与已删——工作区不得成为隐私隔离后门），否则出现「显示 0 条却删不掉」的灵异体验。
2. **防呆下沉动作层**（goodshare-arch）：非空检查落 `_deleteWorkspace`，UI/MCP/AI 三端同守门——现 MCP 侧可无守门直删，违反 Human-AI 对称性硬约束；AI 侧拒绝须带 hint（非空 N 条 + 去向说明）。
3. **条目去向必须明示**：任何「移除」动作（移出工作区/删除条目）后 Snackbar 写明去与留，不许静默。

## 3. 交互方案（本轮评估，待拍板）

### 3.1 列表层：单删，不做多选

- 入口形态：**长按工作区卡 → 底部弹层（重命名/删除）**，沿用全局长按动作语言；删除项红字 + 二次确认（「删除类必确认」既有规则）。
- 不做工作区层多选（有意的不对称）：工作区个位数、破坏性高于条目批量；列表右下角 FAB 与选择底栏冲突；仅列表层有删除入口同时天然排除「正在浏览的工作区被删」的态。
- 空工作区删除走轻量确认；非空走 §3.2 守门。

### 3.2 非空守门：B 快捷删（2026-10-05 拍板 D-WS1；A 方案留档未采纳）

守门提示给具体条数（「这个工作区还有 N 条内容」），不抽象拒绝。~~出口二选一或并存~~：

- ~~**A 强守门**~~：未采纳——六步清空链对「内容也不要了」的用户重摩擦。
- **B 快捷删（定稿）**：弹窗双按钮——「保留内容并删除」（danger 主按钮，文案明示条目回到「全部」）/「取消」。守门下沉动作层：`ackNonEmpty` 仅 ui actor 可携（D-WS2），AI 端非空删除一律拒绝。

### 3.3 清空链路（降为独立候选）

- 「移出本工作区」批量动作（2026-10-05 转正落地）：移除=解除归属回「全部」，**不删条目**；文案与「删除条目」严格分开（Snackbar 明示「条目保留在全部」）。

### 3.4 反馈与边界

- 删除成功 Snackbar「已删除工作区「X」，条目已保留」；**不做撤销**（关系级联不可简单逆，重建需逐条重新归属）。
- 最后一个工作区删除后落既有空态视图（「还没有工作区/点右下角 + 新建」）。

## 5. 拍板决议（2026-10-05，用户确认）

- **D-WS1 = B 快捷删**：非空弹窗「保留内容并删除」danger 主按钮 + 取消；不做强守门/深链清空。实现：空区 `confirmDialog` 轻确认；非空带条数 content；确认后携带 `DeleteWorkspaceCommand.ackNonEmpty=true`。
- **D-WS2 = 同守门**：`ackNonEmpty` 仅 `CommandActor.ui` 可携——非空删除 AI actor 一律拒绝（无 ack=invalidRequest 带条数与去向 hint；带 ack=forbidden）；MCP 工具描述同步明示。计数与列表同口径（排除 Vault/已删，不泄露保险箱条目数）。
- **D-WS3 = 重命名随批**：长按弹层一并做，复用整页创建表单（`initialName` 预填 + 隐藏创建定位语 +「保存」），`RenameWorkspaceCommand` 已有命令层零新增。
- **落地注记**：测试钉住三口径（无 ack 拒绝含条数 / ui ack 删壳条目保留 / ai ack 仍拒）；删除成功 Snackbar 直接回写 `CommandResult.note`（含保留条数）；「移出本工作区」批量转正已于 2026-10-05 落地（§3.3）。
